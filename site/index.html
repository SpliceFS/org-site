Get to your data faster. Keep working when a server fails.

SpliceFS serves your files from all of your servers at once. Today that makes reading faster and keeps it going through an outage. It is growing into a complete distributed file system, with writing, built-in redundancy and control over where your data lives.

Install See how it works

What it does today

  • Go fasterEvery server you add makes access faster, because all of them send data at the same time. Three servers that can each send 300 Mbit/s can give one reader up to 900.
  • Stay upWhen a server slows down or fails, the others cover for it while people keep working. No single machine holds your team up.
  • Spend lessIt is free and open source, and it runs on the servers and disks you already have. No special hardware.
  • Start without a migrationYour files stay where they are, as they are. Try it next to what you run today, and take it away again without losing anything.

What it is growing into

Reading is the first step. These are planned and not built yet.

  • Write from anywhereTeams in every location change the same data, and a change lands everywhere or not at all.
  • Redundancy built inGroups of servers hold data together, so losing one server loses nothing.
  • Every program just worksLocks and full POSIX behavior, so the software you already use needs no changes.
  • Data where you want itRules decide which locations hold which data, for one file or for everything.

See the plan

Is it for you today?

A good fit
  • You keep the same files on two or more servers, in one place or in several.
  • People mostly read them: media, archives, data sets, releases.
  • The connection of one server is your speed limit.
Not yet
  • Your programs need to change the files. Writing is planned.
  • You want it to keep the servers in step. Today the sync tool you already use does that, for example Syncthing or rsync.
  • You need something proven. SpliceFS is new and has not run in production.

Where it stands

SpliceFS is at version 0.x. It reads and does not write yet, and it has not run in production. These pages say plainly what works today and what is only planned.
